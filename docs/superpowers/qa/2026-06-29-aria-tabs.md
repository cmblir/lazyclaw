# QA — Accessible dashboard tab nav — 2026-06-29 (autonomous Q2)

The 18→19 dashboard tabs now implement the WAI-ARIA Tabs pattern with keyboard
navigation and deep-linking.

## What changed
- `nav.tabs` → `role="tablist"`; each button → `role="tab"`, `id="tabbtn-<name>"`,
  `aria-controls="tab-<name>"`, `aria-selected`, and roving `tabindex` (0 active,
  −1 otherwise). Each panel → `role="tabpanel"`, `tabindex="0"`,
  `aria-labelledby="tabbtn-<name>"`.
- Keyboard: ←/→ (and ↑/↓), Home, End move focus + activate within the tablist.
- The URL hash (`#<tab>`) is the source of truth — the active tab survives a
  reload and is deep-linkable. A `hashchange` listener is the single activation
  path; clicks and keyboard both go through it.

## Verification (live, daemon on :19600)
- Deep-link: `GET /dashboard#status` → Status tab active on load (`aria-selected=true`,
  `tabindex=0`); a non-active tab carries `tabindex=-1`, `aria-selected=false`.
- Click `Teams` → `location.hash === '#teams'`, active=teams.
- Keyboard ArrowRight from Teams → Tasks (active + focus moved + `#tasks`); Home → Chat.
- Swept all 19 tabs by click — every panel activated, **0 broken tabs**, **0 console errors**.
- Focus ring already provided by `:focus-visible { outline: 2px solid accent }`
  (covers `button` and `[tabindex]`), so keyboard focus is visible.
- `data-tab="…"` attributes preserved → existing `phase15-dashboard.spec.ts` string
  assertions still hold.
